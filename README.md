# T-Time Playground

Browser tools for testing the T-Time Tibetan input engine, which runs here as
WebAssembly built from the private `ttime` repository. All transliteration rules
live in Rust; the JavaScript only handles events and presentation.

The built `pkg/` contains the T-Time engine compiled from the `ttime` repository under the same licence. Logos and the illustration in `assets/` are project artwork and are not covered by that grant (see below).

## Two things are tested, separately

| Page | Tests | How |
|---|---|---|
| `converter.html` | **Conversion correctness**: does this EWTS give the expected Tibetan Unicode, and back? | Two boxes, edit either; diagnostics, reverse-conversion fidelity, round-trip check, code points, NFC check. |
| `index.html` (Writing Room) | **Typing experience**: can a person enter, edit and copy Tibetan comfortably? | Interactive editor over the composition API: provisional text until space or Enter, then committed. |
| `parity.html` | The Wasm build against the curated fixtures | Runs all 701 fixture cases; tab title shows the result. |

Converting a whole text box does not reproduce native IME composition, so a good
result on the Converter says nothing about typing.

## What is committed

`pkg/` (the built Wasm and JS glue) and `fixtures/` are generated by
`scripts/build-web.sh` in the `ttime` repository and committed here so the site
needs no private build step. `BUILD_INFO` records the `ttime` commit and build time.
To refresh: from `ttime`, run `scripts/build-web.sh` (writes into `../playground`).

Run locally: `python3 -m http.server 8000`, then open http://localhost:8000.

## Tool tabs and the symbol palette

The tools sit in tabs directly under the editor: Latin, Symbols, Inspector, Diplomatic, Output form and Report a problem. Selecting a tab opens its panel; selecting it again closes it. Everything updates live while you type. Modes (Latin, Diplomatic, Output form) stay on when their panel is closed, and their tab shows a dot. New tools for testing are added as tabs.


The Writing Room has a **Symbols** tab, under the editor, that opens a searchable palette
(`palette.js`) of Tibetan punctuation, marks and Sanskrit letters. Search by name,
code point, EWTS or the character; filter by category; **Insert** puts the symbol at the
caret (a pending EWTS run is fixed first) and **Copy** puts it on the clipboard.
The catalogue and the search live in the Rust core (`ttime-core`, `data/symbols.tsv`)
and arrive through the Wasm package. It is a draft: sequences are checked against the engine,
labels are not reviewed by a Tibetologist.

## Writing Room behaviour and limits

- Typed text is provisional (highlighted) until space or Enter. A space inside
  `[...]` or after a backslash does not end the run.
- EWTS typing is intercepted only with the caret at the end. Elsewhere, and for
  paste and cut, the browser edits normally and the result is adopted as committed text.
- Backspace removes the last typed letter of the provisional run; with none, the
  browser deletes committed text.
- Input methods that use composition events (most phone keyboards) bypass EWTS typing.

## Design and assets

Visual design only; the engine, fixtures and conversion behaviour are untouched.
Colour and type tokens live at the top of `style.css`, light and dark via
`prefers-color-scheme`. Motion respects `prefers-reduced-motion`.

- `assets/logo-long.svg` and `assets/logo-long-dark.svg` (wide lockups for light and dark mode) and `assets/logo-square.svg` (icon, used as the favicon): supplied logos, unmodified.
- `assets/logo-long.webp` and `assets/logo-long-dark.webp`: the header versions of those two lockups, derived from the SVGs by removing the flat background colour (so they sit on the page colour) and scaling to 720 px wide. The SVGs remain the originals.
- `assets/typing.webp`: the supplied `typing.png`, trimmed and resized, converted to WebP. Project artwork, not under the code licence.
- `assets/fonts/`: Newsreader (roman and italic) and Noto Serif Tibetan, woff2 conversions (subsetting is permitted for these two), under the SIL OFL 1.1 (texts alongside; neither font declares a reserved name). Source Sans 3 and Jomolhari were not bundled because their reserved font names forbid modified or subset versions. Sans and mono use system stacks; Jomolhari is selectable in the Writing Room only if installed.

## Verification status

Checked: native Rust tests; parity 701/701 in the Claude desktop app's
Chromium-based browser; typing, backspace, examples and bidirectional conversion
by hand there; copy buttons by a real click; light and dark, desktop and 375px mobile renders inspected in the same browser; no network requests beyond the local files.
**Not checked:** Safari, Firefox, Windows, Linux, phone keyboards, screen readers,
other fonts, deployment.

## Reporting problems

Both tools have a "Report a problem" section. It builds a text report in the page (version, browser, text, code points, what you expected). "Copy report" puts it on the clipboard; "Report on GitHub" opens a pre-filled new issue on this repository, which the reporter reviews and submits themselves. Nothing is sent by the page. Issues are public, and the report text is truncated to 6000 characters in the link.

## Privacy

Conversion runs in the browser; nothing is sent. Feedback reports are built
locally and copied by the user. A hosting provider may keep ordinary access logs.
The page is public to anyone with the link once deployed.
